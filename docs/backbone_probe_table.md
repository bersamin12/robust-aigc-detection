## Reading this table

**`dim` is not a footnote.** `train_head` takes `dim_feat=bank.config["dim"]`, so a wider bank is handed a bigger head and a wide arm that wins has two explanations available.
Here `convnextv2h` is 5.5x the width of `dinov3l`. If it wins, re-run the best rung of the narrowest arm with `hidden` raised to match its head's parameter count before calling it a finding -- a CPU-only Stage B run of minutes.

**`dtype` is what the entry declares.** A `bfloat16` spec on a Kaggle T4 or P100 has no hardware for it, so `run_dtype` degrades to `float32`: the same numbers at roughly 3x the time. A slow arm is evidence about the GPU, not about the tower.

**Two caveats travel with every number above.**

- *Scale.* 20,000 rows against the corpus's 375,358. This ranks candidates; it does not settle the shipped choice.
- *Population.* Arms sourced from `docs/robustness_table.md` were measured on the frozen 138,116-row corpus, a different population from the union probe.

**One pair is not an architecture comparison.** `siglip2l` keeps ImageNet normalisation because its banks were built that way, while `siglipso400m` uses SigLIP's own `[0.5]*3`. A gap between those two confounds the tower with the preprocessing (`src/aigcdet/features/backbones.py`, see `IMAGENET_MEAN`).
